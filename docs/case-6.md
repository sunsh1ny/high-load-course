# Кейс 6: повторные попытки оплаты

Условия: аккаунт `acc-8`, 7 покупок/с, 800 покупок и общий дедлайн оплаты
3500 мс. У аккаунта лимит 10 вызовов/с, 50 параллельных запросов,
среднее время обработки 700 мс и стоимость попытки 30.

## Решение

В профиле `case6` разрешены максимум три последовательные попытки.
Повтор выполняется только после явного `result=false` в корректном ответе
HTTP 2xx либо HTTP 500/502/503/504. После успеха обработка сразу прекращается.
Таймауты, повреждённые ответы, ошибки авторизации и нарушения лимита
не повторяются.

Паузы перед второй и третьей попытками — 50 и 100 мс. Перед повтором
проверяется, остаётся ли время на паузу и среднюю обработку плюс 100 мс.
Все попытки используют исходный дедлайн и общий ограничитель аккаунта.
Встроенные повторы OkHttp при ошибках соединения отключены.

У покупки сохраняется `paymentId`, каждая попытка получает новый
`transactionId` и событие отправки. Окончательный результат платежа
записывается один раз. Для остальных профилей по умолчанию остаётся
одна попытка.

## Запуск

После запуска инфраструктуры задать `PAYMENT_SERVICE_NAME` и `PAYMENT_TOKEN`:

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=case6
```

Нагрузочный запрос находится в `test-case-6.http`. Для приложения на порту
8081 используется `onPremises: false`.

## Проверка

`mvn test`: 27 тестов без ошибок. Проверяются повтор после явного отказа,
остановка после успеха, число попыток, сохранение идентификаторов и одного
финального результата, постоянные ошибки, недостаточный остаток времени
и неоднозначный сетевой таймаут.

По графикам предоставленного локального прогона общая успешность — около
99,12%, доходы/расходы — около 92,6/7,42, частота вызовов провайдера с учётом
повторов — до 8/с. Это укладывается в финансовый ориентир 92/8, но ниже
строгого 93/7. Минимальная успешность всех минутных окон отдельно не проверена.

Для точного подсчёта выбирать один источник Prometheus, например
`job="bombardier-docker-network-job"`: текущая конфигурация также собирает
тот же Bombardier через `bombardier-host-job`. Абсолютные количества на общем
дашборде поэтому завышены, а `increase` может давать дробные оценки.
