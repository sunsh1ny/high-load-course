# Кейс 5: ограничение приёма платежей

Аккаунт `acc-23` допускает 11 вызовов в секунду и 64 параллельных
запроса. Среднее время обработки — 1 секунда.

## Решение

`PaymentAdmissionLimiter` ограничивает количество реально незавершённых
платежей до помещения в `PaymentBuffer`. Лимит зависит от оставшегося
времени покупателя:

```text
интервал вызовов = 1,01 секунды / 11
доступное время = deadline - now - 1200 мс
лимит незавершённых платежей = floor(доступное время / интервал) + 1
```

При отрицательном доступном времени запрос отклоняется. Для трёх дедлайнов
получаются примерно 15, 129 и 271 место соответственно. Длинный дедлайн
позволяет принять пакет из 270 покупок.

Место освобождается после завершения задачи, ошибки или пропуска просроченной
задачи. Если поставить задачу в буфер не удалось, место также освобождается.
Повторное освобождение безопасно.

При исчерпании мест контроллер возвращает HTTP 429 с `Retry-After`.
В используемой версии Bombardier значение заголовка — абсолютное время
повтора в миллисекундах Unix, а не стандартная HTTP-задержка в секундах.

`PaymentAccountRateLimiter` равномерно распределяет вызовы провайдера,
оставляя 1% на задержки транспорта и планировщика. После паузы накопленные
разрешения не выдаются пачкой. Ограничение параллельности сохраняется.

В профиле `case5` используется 32 рабочих потока; ёмкость существующего
буфера остаётся стандартной — 256. Остальные профили не включают входной
ограничитель.

## Запуск и проверка

Задать `PAYMENT_SERVICE_NAME` и `PAYMENT_TOKEN`, запустить инфраструктуру
из `docker-compose.yml`, затем:

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=case5
```

Три запроса преподавателя находятся в `test-case-5.http`. Запускать их
последовательно. Для приложения на локальном порту 8081 используется
`onPremises: false`. Нагрузочные параметры задания не изменены.

Собственные метрики:

- `payment_admission_pending` — незавершённые платежи;
- `payment_admission_accepted_total` — выданные разрешения на приём;
- `payment_admission_rejected_total` — отказы входного ограничителя.

Для результатов Bombardier выбирать один источник Prometheus, например
`job="bombardier-docker-network-job"`: в текущей конфигурации один сервис
собирается также через `bombardier-host-job`, и суммирование обоих источников
завышает абсолютные количества.

Unit-тесты (`mvn test`) проверяют ограничение при конкурентном приёме,
освобождение мест, истечение задач, HTTP 429 и исходящую частоту.
Они не заменяют нагрузочную проверку. Общая успешность выше 97% сама по себе
не подтверждает требование выше 97% в каждом минутном окне; полное прохождение
всех трёх сценариев пока не подтверждено.
