# Кейс 5: управление приёмом платежей

- **Причина:** нагрузка превышала возможности провайдера или приходила большими пакетами. Платежи накапливались в очереди и не успевали до дедлайна; ограничение только исходящих вызовов этого не предотвращало.
- **Решение:** ограничили число реально незавершённых платежей с учётом оставшегося времени. При перегрузке возвращаем `429` с `Retry-After`, а вызовы провайдера распределяем равномерно в пределах его лимита.
- **Почему помогло:** место для нового платежа освобождается по фактическому завершению предыдущего. Это сдерживает накопление работы, позволяет принимать всплески в пределах дедлайна и уменьшает число клиентских таймаутов.
